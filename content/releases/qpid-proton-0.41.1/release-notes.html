Qpid Proton 0.41.1 Release Notes

Proton is a high-performance, lightweight messaging library. More about Qpid Proton.

For more information about this release, including download links and documentation, see the release overview.

New features and improvements

  • PROTON-1442 - [c++] Support for transactions
  • PROTON-1646 - Proactor API needs a way to use an existing socket.
  • PROTON-1779 - Completely omit default HEADER and PROPERTIES sections from message payload
  • PROTON-2502 - Stop using deprecated (and insecure) SASL mechanisms based on MD5
  • PROTON-2868 - Improve and simplify the scheme for wrapping C Proton objects in Python
  • PROTON-2871 - Make the generated AMQP protocol constant names more explicit
  • PROTON-2873 - Reorganize delivery disposition API and representation
  • PROTON-2881 - Modernize python code
  • PROTON-2888 - Add std::hash specializations to allow more proton types as keys in unordered datastructures
  • PROTON-2889 - Improve C++ example broker
  • PROTON-2890 - [Python examples] Improve python examples
  • PROTON-2891 - Improve python type annotations
  • PROTON-2892 - Model Endpoint state with builtin python IntFlag
  • PROTON-2893 - Add on_delivery_updated callback to MessagingHandler
  • PROTON-2898 - Introduce API to proton proactor that allows importing an already connected socket
  • PROTON-2909 - [Test] SSL certificates used for testing are duplicated and scattered
  • PROTON-2910 - Use better names for generated frame codec functions
  • PROTON-2911 - [C++] Terminus capabilities which are single symbols incorrectly handled
  • PROTON-2916 - C++ reconnect test takes a very long time
  • PROTON-2921 - [C++ transactions] Better control of message settlement/disposition behaviour
  • PROTON-2922 - [C++ transactions] Better CI testing of C++ transactions
  • PROTON-2926 - Improve documentation and some behaviour when message ttl = 0
  • PROTON-2932 - C++: Add std::hash specialized for transfers so they can be keys for unordered data structures
  • PROTON-2936 - [C++] There is no way to detect when the proactor is idle
  • PROTON-2946 - Interop round trip tests should use a semantic comparison
  • PROTON-2958 - Implement small AMQP encodings for list/maps/arrays in pn_data_t encoder
  • PROTON-2961 - Make CMake use of libuv align with the libuv conventions
  • PROTON-2966 - pn_decoder_decode does not report why a decode failed
  • PROTON-2967 - Decode AMQP values iteratively rather than recursively
  • PROTON-2969 - Stop pn_value_dump from reading more input when the output is full
  • PROTON-2979 - Omit optional fields on continuation transfers.
  • PROTON-2981 - The windows API being used should be explicitly 6.1
  • PROTON-2985 - Add random perturbation mode to threaderciser
